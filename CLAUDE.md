# Dog Training App & Website

A static, multi-page website for tracking dog training: logging sessions, managing commands, viewing history and charts, setting daily goals, and command mastery. Plain HTML/CSS/JS, with no build step or framework. Supabase provides accounts and cloud data.

## Layout

Code is split into **shared** (used by several pages) and **pages** (one file per page, named after the page).

- `index.html` (repo root): redirects to `src/HTML/index.html`, so the GitHub Pages site root works.
- `src/HTML/`: pages. `index.html` is the home page: a green banner with the main actions and a dog medallion (`index.js`: the dog you're training with ‹ › to switch, in a ring that fills toward the daily goal picked on Today), over a grid of page tiles. Others: `today`, `commands`, `log`, `load` (view logs, training/exercise time totals, Plotly charts and a command timeline with practice breaks, filtered by a "Switch dog" picker), `dogs` (My Dogs: a card per dog with its profile (breed, birthday/age, notes) and training stats; add, edit, delete and pick the current dog; each card links to its chart), `dog` (`dog.html?id=…`: one dog's full chart of basics, health & vet with vaccinations/medications, care & routine, and behavior; fields are declared in `CHART_SECTIONS` in dog.js; `type: "chips"` fields are pick-any bubbles saved as an array, with an add-your-own box and a notes box), `settings`, `upcoming` (planned features), `directory`, `create` (sign up), `login`. Signed-in users opening `create`/`login` are sent to `settings`.
- `src/CSS/shared/`: every page loads `base.css` (color tokens, layout, headings, section cards), `nav.css` (top bar: the Tea Time site name, Directory dropdown, account links), and `forms.css` (buttons, fields, toggle switches), in that order. Every page's `.top-nav` starts with the `.nav-brand` link; `accountNav.js` marks the current page in the Directory menu (`aria-current`).
- `src/CSS/pages/<page>.css`: styles for one page, loaded after the shared files. `auth.css` is shared by `create` and `login`.
- `src/JS/shared/`:
  - `supabaseClient.js`: the global `supabaseClient` (project URL + anon key), `getSignedInUser()`, `localDateString()`. `supabaseClient` is `null` when keys aren't set or the CDN didn't load, so check it before using Supabase.
  - `commandList.js`: each account's added and removed commands (`getCustomCommands`, `getHiddenCommands`, `saveCommandLists`, `saveCustomCommands`, `saveHiddenCommands`), cached in localStorage `customCommands` / `hiddenCommands` and synced with `account_settings.custom_commands` / `hidden_commands` (fires `commandlistsynced`). Signed out, the lists belong to the browser; an account that never saved lists adopts the browser's; log out clears them back to the defaults. Always save through these functions, never write those keys directly. Loaded on every page, right after `supabaseClient.js`.
  - `accountNav.js`: when signed in, turns the top nav's Create Account / Login links into the user's display name + email (to `settings.html`) and Log Out. Display name is `user_metadata.display_name` (the settings page writes it there and to `account_settings.display_name`), falling back to the sign-up `username`. Load after `supabaseClient.js`.
  - `trainingData.js`: localStorage helpers (`getAllCommandNames` over `BUILT_IN_COMMANDS` + `customCommands`, `SUGGESTED_COMMANDS` for the Commands page's add suggestions, duration formatting/parsing), plus daily goals synced with Supabase `training_goals` and `account_settings.active_goal_type`. Save with `saveGoal()` / `saveActiveGoalType()` (they update the `today*Goal` cache too). It syncs on page load and fires `goalssynced` (`detail.changed`). Cached goals are tagged with their account and cleared on log out.
  - `dogs.js`: the account's dogs (`getDogs`, `createDog`, `ensureFirstDog`) and the selected dog (`getCurrentDogId`). Loaded on `today`, `load`, `settings`, `log`, `dogs`, `dog`, `commands`, `create` and `login`, after `supabaseClient.js` and before `sessions.js`. `updateDog` saves a dog's name and profile, plus its chart (`dogs.profile` JSON) when given. The `dogs` page adds, edits and deletes dogs and picks the current one (deleting a dog also deletes its sessions); signing in selects one of the account's dogs.
  - `sessions.js`: training session history, synced with Supabase `training_sessions`. Pages read with `getSessionHistory()` and write the whole list with `setSessionHistory()`. It works out adds, edits and deletes and syncs them, so never write `localStorage.sessionHistory` directly. It syncs on every page load and fires a `sessionhistorysynced` event (`detail.changed`, `detail.uploaded`) for pages to redraw. Each session's `id` is its Supabase row id, `dogId` is stamped once when it's first saved (from `getCurrentDogId()` if `dogs.js` is loaded, else null), and `updatedAt` decides which copy wins when two devices edit it. On log out, pending sessions are uploaded and this browser's copy is cleared. Loaded on every page, after `supabaseClient.js`.
  - `commandDisplay.js`: per-command display settings (`getCommandDisplay`, `setCommandDisplay`, `renameCommandDisplay`) cached in localStorage `commandDisplaySettings` and synced with `account_settings.command_display` (fires `commanddisplaysynced`). Set in Commands > Display Settings; the Log form and Today's add/edit forms hide rows marked `data-display-field`, and Today session cards leave those fields out. Its `masteryDecay` field turns decay off for one command in Command Mastery (the account-wide decay toggle still has to be on).
  - `commandNotes.js`: per-command free-text notes (`getCommandNote`, `setCommandNote`, `renameCommandNote`) cached in localStorage `commandNotes` and synced with `account_settings.command_notes` (fires `commandnotessynced`). Shown in a command tile's panel and edited in its notes pop-up; cleared on log out. Loaded on `commands`.
  - `mastery.js`: `getCommandMastery()`, tiers, and the `mastery_decay_enabled` setting.
  - `tasklists.js`: CGC task-list seeding and progress in Supabase.
- `src/JS/pages/<page>.js`: the script for one page. `auth.js` serves `create` and `login`.
- Each page's `<head>` lists shared styles/scripts first, then its own. Scripts are classic (not modules) with `defer`, so shared top-level functions are globals and load order matters.
- `supabase/schema.sql` then `supabase/command_mastery.sql`: tables, RLS policies, and the `get_command_mastery()` function. Run in the Supabase SQL editor; both are safe to re-run. `supabase/account_display_name.sql` (run after) backfills `account_settings.display_name` from existing accounts' metadata. `supabase/training_goals.sql` (run after `command_mastery.sql`) adds `training_goals` and `account_settings.active_goal_type`. `supabase/command_display.sql` (also after `command_mastery.sql`) adds `account_settings.command_display`, and `supabase/session_score_weather.sql` adds `training_sessions.score` (1-10) and `weather`. `supabase/dog_profiles.sql` (after `schema.sql`) adds `dogs.breed`, `birthday` and `notes`, and `supabase/dog_chart.sql` (after that) adds `dogs.profile`. `supabase/command_notes.sql` (after `command_mastery.sql`) adds `account_settings.command_notes`, and `supabase/command_list.sql` adds `account_settings.custom_commands` and `hidden_commands`.
- `tools/run-in-node.js`: runs a page's scripts under Node + jsdom (used by `.vscode/launch.json`).

Pages reference assets relatively (`../CSS/...`, `../JS/...`). Folder names HTML/CSS/JS are uppercase; keep references matching exactly since web hosts are case-sensitive.

## Data

- Collapsible sections use `<details open><summary class="collapsible-toggle">…</summary>…</details>` (styles in `base.css`).
- Most data is in `localStorage` as JSON (keys like `sessionHistory`, `exerciseHistory`, `customCommands`, `hiddenCommands`, `today*Goal`, `cgcAttempts`). Use `getVisibleCommandNames()` (trainingData.js) for pickers that log new sessions, and `getAllCommandNames()` where removed commands' history still matters.
- Supabase tables: `dogs`, `task_lists`, `task_list_items`, `dog_task_progress`, `training_sessions`, `training_goals`, `account_settings`, `mastery_tiers`. Rows are scoped to `auth.uid()` through RLS.
- Mastery: `base_level` is the best tier ever earned from session history (never drops); `decayed_level` walks down one tier each time idle days exceed that tier's `decay_after_days`. The account's `mastery_decay_enabled` picks which one is displayed. Tune tiers by editing `mastery_tiers` rows, not code.
- Always call the client `supabaseClient` (the CDN library owns the global name `supabase`). Only the anon key belongs in frontend code, never the service_role key.

## Running

- Open `src/HTML/index.html` in a browser (or use a Live Server extension). No build needed. Supabase auth works best served over http (Live Server) rather than `file://`.
- `node tools/run-in-node.js <page>` loads that page's local scripts under jsdom (CDN scripts like Plotly/Supabase are skipped). Run `npm install` first.
- No tests or linter are configured.

## Conventions

- Short lowercase `//` comments above functions describing what they do.
- LF line endings, UTF-8 without BOM.
- Colors and shadows come from the tokens in `base.css` (`--moss`, `--danger`, `--shadow-card`, ...); add a token rather than a new hex value. `--moss` and `--muted` are tuned for readable contrast (white on moss 4.8:1, muted on the page 5.2:1), so keep text on those colors at least that dark. Use `.save-btn` for a card's one main action and the shared outlined `.secondary-btn` for the rest. Section cards fill the page width. Stat tiles (`.stat-row`/`.stat-tile`) and `.visually-hidden` are shared in `base.css`, as are pop-ups (`.modal-overlay` > `.modal-card`, shown by toggling the overlay's `hidden`).
- Font sizes are in `rem` (1rem = 16px on phones). `base.css` raises the root size on screens 900px+ wide to `clamp(18px, 1.4vw, 36px)` (about 27px on a 1920px monitor). Spacing, widths, radii and shadows are in `rem` too, so the whole page scales like browser zoom; use `rem` for new sizes (borders stay 1px) or they won't scale.
- Fonts: Newsreader (Google Fonts) for everything: headings, body, form controls and charts. Use no other font. Charts: Plotly from CDN (`load.html`); draw them with `plotChart()` in load.js so their text and margins scale with the page.
